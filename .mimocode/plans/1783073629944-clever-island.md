# Plan: Separate Front-End from Back-End

## Context

The project has two Presentation class libraries (`SM.Presentation` and `IM.Presentation`) that contain API controllers. Since the goal is to separate Front-End (ServiceHost) from Back-End (LampShade.Api), these Presentation projects should be removed. LampShade.Api already has comprehensive CQRS/MediatR controllers for all modules — the Presentation projects are redundant except for one endpoint.

## Current State Analysis

| Project | Endpoints | Used By |
|---------|-----------|---------|
| **SM.Presentation** | `GET /api/Product` (LatestArrivals), `GET /api/Product/{value}` (Search) | ServiceHost references it, but ViewComponents call `IProductQuery` directly. **NOT used.** |
| **IM.Presentation** | `GET /api/Inventory/{id}` (Operations), `POST /api/Inventory` (CheckStock) | ServiceHost references it. `custom.js` calls CheckStock. |
| **LampShade.Api** | Full CQRS controllers for all modules | Back-End API |

**Only one endpoint is still needed**: `CheckStock` — called by `ServiceHost/wwwroot/Theme/assets/js/custom.js:78`.

## Implementation Plan

### Step 1: Add CheckStock to LampShade.Api

Create a new MediatR query following the existing CQRS pattern:

**New files:**
- `LampShade.Api/Features/Inventories/Queries/CheckStock/CheckStockQuery.cs` — Query class with `ProductId` and `Count` properties
- `LampShade.Api/Features/Inventories/Queries/CheckStock/CheckStockQueryHandler.cs` — Handler that calls `IInventoryQuery.CheckStock()`

**Modified file:**
- `LampShade.Api/Controllers/Read/InventoryQueryController.cs` — Create new file with `POST /api/read/inventory/checkstock` endpoint

**Key references:**
- Existing pattern: `LampShade.Api/Features/Inventories/Queries/SearchInventories/`
- Contract: `01_LampShadeQuery/Contract/Inventory/IInventoryQuery.cs` (line 5: `StockStatus CheckStock(IsInStock command)`)
